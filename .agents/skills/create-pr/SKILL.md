# Create PR

## 실행 주체

- 부모 에이전트는 `collaboration.spawn_agent`로 PR 생성 전담 서브에이전트를 실행한다. 실제 분석·본문 작성·push·PR 생성은 그 서브에이전트가 수행한다. 서브에이전트로 이 스킬을 받은 경우 다시 위임하지 않고 직접 실행한다.
- 위임에는 저장소 절대 경로, 이 SKILL.md 경로, 사용자 원문 요청, 알려진 검증 결과와 미해결 사항, 대상 브랜치·언어·draft 지정 및 승인 범위를 전달한다. 공유 작업 디렉토리를 동시에 변경하지 않는다.
- 서브에이전트를 사용할 수 없으면 그 제한을 알린다. 부모가 조용히 PR 생성을 대신하지 않는다.
- 부모는 완료 결과를 기다리고, 반환된 PR URL·대상 브랜치·검증 결과를 사용자에게 전달한다. 서브에이전트의 질문이나 실패도 숨기지 않는다.

## 저장소와 변경 범위 확인

- 적용되는 AGENTS.md, CONTRIBUTING, 저장소의 PR 템플릿과 작성 규칙을 읽는다. Git 상태, remote, 현재 브랜치, upstream, base 대비 커밋과 diff를 확인한다. 기본 브랜치 이름이나 origin이 제출 대상이라고 추측하지 않는다. fork라면 제출 저장소와 head 저장소를 구분한다.
- PR 생성 요청은 해당 PR에 필요한 현재 작업 브랜치의 일반 push와 PR 생성을 허용한다. 사용자 지시가 더 좁으면 그 범위를 따른다. 스킬 자동 선택만으로 외부 변경 권한이 생기지는 않는다. 본문 초안만 요청했다면 push·PR 생성을 하지 않는다.
- 미커밋 변경은 PR에 포함되지 않음을 확인한다. 사용자가 커밋까지 요청했으면 프로젝트의 커밋 지침으로 처리하고, 그렇지 않으면 미커밋 변경을 알리고 포함 여부를 확인한다. 사용자 변경을 자동으로 커밋하거나 버리지 않는다.
- 필요한 검증을 실행하거나 이번 변경에 대해 이미 수행된 검증 근거를 확인한다. 실행하지 못한 검증과 실패를 본문에 정확히 기록한다. PR 작업을 이유로 무관한 구현·리팩터링을 추가하지 않는다.

## 언어와 템플릿 선택

PR 제목과 본문은 같은 언어를 사용한다. 다음 근거를 순서대로 적용한다.

1. 사용자가 지정한 언어.
2. 제출 대상 저장소의 명시적인 기여·PR 언어 규칙.
3. 최근 PR 및 CONTRIBUTING·README의 주 사용 언어. 해외 오픈소스처럼 영어로 기여하는 프로젝트는 영문, 한국어로 협업하는 프로젝트는 한국어를 선택한다. 사용자 대화 언어나 저장소 소유자의 국적만으로 판단하지 않는다.
4. 근거가 혼재해 선택이 어려우면 언어만 짧게 질문한다.

사용자 지정과 필수 기여 규칙이 충돌하면 제출 전에 충돌을 알리고 해결한다. 선택한 언어의 참조만 읽는다.

- 영문: [references/pr-template.en.md](references/pr-template.en.md)
- 한국어: [references/pr-template.ko.md](references/pr-template.ko.md)

제출 저장소에 필수 PR 템플릿이 있으면 그 구조·체크리스트를 우선하고 선택한 참조의 작성 기준을 적용한다. 필수 템플릿이 없으면 참조의 본문 틀을 사용한다. 체크리스트의 완료 여부를 근거 없이 표시하지 않는다.

## PR 작성과 생성

- 최종 diff를 기준으로 문제와 변경 후 동작을 먼저 설명한다. 제목은 구체적인 변경 결과를 표현하고 저장소의 제목 관례를 따른다. 대화 이력이나 폐기한 접근은 리뷰 판단에 필요할 때만 담는다.
- base/head와 대상 저장소를 확정하고 동일 head/base의 기존 열린 PR을 확인한다. 이미 있으면 URL을 반환한다. 기존 PR의 수정 요청이 없으면 덮어쓰지 않는다.
- 연결된 GitHub 도구로 가능한 작업은 해당 도구를 우선한다. 필요한 기능이 없으면 인증된 `gh`와 Git CLI를 사용한다. CLI로 본문을 전달할 때는 임시 UTF-8 파일에 실제 줄바꿈을 보존해 쓰고 `--body-file`로 전달한다.
- 생성 직전에 브랜치와 변경 범위를 재확인하고 필요한 경우 해당 head 브랜치만 일반 push한다. 기본·보호 브랜치에서 작업 중이면 `codex/` 접두사의 작업 브랜치를 사용한다. force push, 이력 재작성, merge, reviewer 지정 등 추가 외부 작업은 별도 요청 없이 수행하지 않는다.
- 사용자 또는 저장소 규칙에 따라 draft 여부를 결정한다. 별도 지정이 없고 제출 준비가 완료되면 일반 PR을 생성한다. 중대한 검증 실패로 준비가 안 됐으면 상태를 알리고 draft 제출 여부를 확인한다.
- 생성 요청이 시간 초과되거나 결과가 불명확하면 같은 head/base의 PR 존재 여부부터 조회한다. 생성 여부를 확인할 수 없으면 중단하고 보고하며 중복 생성하지 않는다. 인증·권한·원격 거부는 원인을 알리고 중단한다.
- 생성된 PR을 다시 조회해 URL, base/head, 제목·본문을 확인한다. 완료 보고에는 URL, 선택 언어와 근거, 검증 결과·미실시 항목, 남은 로컬 변경을 포함한다.
