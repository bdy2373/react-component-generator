# English PR template

Use English for the title and body. Lead with the concrete problem and resulting behavior. Scale the detail to the change; a small PR needs only a short summary and validation. Replace the guidance in parentheses with evidence from the final diff. Remove optional sections when irrelevant, and never invent test results or issue numbers.

```markdown
## Summary

(Explain the problem and what this change enables or fixes. Include a before/after example when useful.)

## Validation

(List checks actually run and their results. State checks not run and why.)

## Risks and limitations

(Optional: material compatibility concerns, known limitations, or follow-up work.)

## Related issues

(Optional: link verified related issues. Use closing keywords only when the PR resolves the issue.)
```

For visual changes, attach available screenshots when they help review. Never claim screenshots exist when none were captured. Follow the destination repository's required template and checklist when present.
